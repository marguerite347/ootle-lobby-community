# Finding and integrating creative assets

Use with the [resource-first workflow](../../.agents/skills/resource-first-workflow/SKILL.md)
and [creative operating rules](../agents/CREATIVE_OPERATING_RULES.md).
The [accepted AI Spark crystal](components/AISparkCrystal/README.md) is a worked
example, not a mandate to use the same effect everywhere.

## Select the finished visual, not just its engine

1. Describe the visible result: silhouette, scale, motion path, pacing, depth,
   palette and interaction. Turn expressive direction into observable criteria.
2. Inspect current project assets, licenses, capture workflows and available tools.
   Reuse a matching finished asset first. A particle library is a renderer, not an
   art-directed effect. Installing a library does not fulfill a request for polished
   existing animation. If the user asks not to author an effect, honor that constraint.
3. Shortlist a few concrete assets. Prefer an original motion preview over a
   thumbnail, title or vendor description. Inspect the whole loop, including blank
   frames, seams, tails and crop boundaries. Show the strongest source in motion
   before substantial adaptation when creative direction is unresolved.
4. Verify actual entitlement, item identity, license and suitability for the intended
   end product. Check dimensions, alpha, codec, duration, frame rate, looping,
   editable files, runtime compatibility and size. A signed-in account or vendor's
   "looped" label alone is not proof. No new purchase or access beyond authorization.
5. Run one small contextual trial before bulk downloads or broad implementation.
   Evaluate the asset next to the real focal object at desktop and phone scale.
   If it fails, revisit the asset choice rather than repeatedly adding particles.

## Adapt without losing the approved character

Preserve the source's defining motion and detail. Recolor, transform and composite
only as needed for the product. Explain material changes to timing or geometry.
Use the licensed master, never a watermarked preview in the implementation.
Keep raw licensed media and credentials out of git. Commit source references,
license status, checksums, reproducible conversion/restore commands and editable
adapters. Provide authorized private storage for media needed by another worker;
a machine-specific path alone is an incomplete portable handoff.

For 3D overlays, inspect the source center and expanding bounds before placement.
Reserve clearance around the actual object, implement front/back depth, and use
one coordinate mapping for both VFX and lights. A video does not cast light by
itself. Document any lighting approximation and tie it to the source timeline.
Feather crop boundaries; inspect the very last visible tail. Match light decay to
visual decay. Never claim physical reflections or volumetric effects when simulated.

## Verify and record

Review a complete loop and frame sheet, not a flattering still. Check peak and
settled compositions, phone framing, pause/resume, reduced motion, effects-off,
loading failures and performance at the intended size. Check reward correctness
separately. Audio remains not auditioned until actually heard.

Record: requirement; candidates and choice; author/item/source/license; actual
access; pinned renderer; source and derivative checksums; conversion command;
trial revision; evidence; user acceptance scope; remaining integration/media gaps;
next owner. Keep source inspected, acquired, adapted, rendered, user accepted,
merged and served as separate states. A rejected visual stays unaccepted until
reviewed again. Do not turn an accepted local proof into a claim of product delivery.
