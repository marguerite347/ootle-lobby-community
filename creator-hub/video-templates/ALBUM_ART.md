# Bespoke Discover album artwork

Every current resource has an explicitly authored scene and art brief in `src/album/scenes.mjs`. The shared `art.mjs` file supplies low-level drawing primitives, not category scenes. `frame.mjs` supplies a common Tari-colored background and caption frame. Each resource's composition and moving subject are individually authored. These are editorial illustrations, not screenshots or evidence of integration.

## Reproduce and publish

1. Install pinned dependencies with `npm ci` here.
2. Run `node scripts/render-albums.mjs`. This creates 640×360, 24 fps, four-second MP4 loops and PNG posters in ignored `out/albums`. Rendering is sequential to avoid shared-browser failures. Existing content-addressed renders are reused; the fingerprint covers the full scene function, shared drawing and composition source, and render settings, so motion-only edits also produce new filenames.
3. Inspect every poster and opposing motion frames, review loop boundaries and the actual card crop, and compare the library for repeated compositions. The draft manifest contains exact resource IDs, briefs, source links and video hashes. Rendering does **not** approve or publish.
4. Create a reviewed approval file with entries `{id, review}` matching `../VIDEO_PREVIEW_POLICY.md`. Approval is a visual decision, not a checkbox generated by the renderer. `faithfulToSource` means semantically relevant artwork, not literal UI fidelity.
5. Run `node scripts/publish-albums.mjs <approval-file>`. It validates reviewed hashes and metadata, copies and verifies temporary files before atomic renames into the hub's configured previews directory and atomically updates the index. Preserve the review record in the repo. Binary outputs remain runtime artifacts.
6. Verify `/explore` on the actual serving host. Reviewed album art takes priority over automatically captured webpage clips; original upstream video remains intact. Source recordings stay on disk. A merge alone does not copy video assets to another host.

For new resources, write a new scene and brief. Unknown titles deliberately fail instead of reusing a stock animation. Never attach existing artwork to an unrelated resource or auto-approve generated output. Keep IDs stable and revise title bindings if the catalog changes. Run `npm test` and `npm run typecheck` here, plus hub preview tests when wiring changes.

See `../VIDEO_PREVIEW_POLICY.md` for the global creative requirement and `../hub/DISCOVER_VIDEO_HANDOFF.md` for runtime context.
