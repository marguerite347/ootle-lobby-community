# Resource selection receipt

Use this small block in the existing PR description or task handoff. Do not create a parallel task database.

- **Result / acceptance:** What must work, and how it will be checked.
- **Looked at:** Relevant local catalogs, scripts, available tools/skills and prior evidence. Link only the useful sources; say what could not be checked.
- **Reuse / why:** Chosen workflow and why it fits better than alternatives. If building new, identify the actual gap in existing capabilities.
- **Availability:** Catalogued, installed, callable, or verified; record the concrete check and version where relevant.
- **Small trial:** Input, outcome, and artifact/evidence location. For an expensive task, complete this before scaling up.
- **Outcome / next reuse:** What succeeded, what failed, validation limits, and the canonical instruction to use next time.

For a simple edit, collapse this to one sentence. Do not manufacture runtime evidence for a documentation-only change.
